# Graph Simulation (ver 2.1.0)

グラフ上での進行波の生存・消滅の実験を視覚化するシミュレーションプラットフォームです。直感的なグラフエディタにより、複雑なグラフを自在に構築し、動的なエージェントベースのシミュレーションを実行できます。
（ほとんどの人にとってこのようなアプリは必要ないのですが、単なるグラフエディターとしてお使い頂けると思います。）

## 🌟 主な機能

### 1. グラフエディター
モード切り替え方式を採用した、直感的な操作感を持つエディタです。
* **ノード設置**: クリック一つでグリッドスナップに対応したノードを配置。
* **エッジ接続**: 2つのノードを選択して辺(エッジ)を形成。
* **自由な移動**: 配置済みノードのドラッグ移動（接続された辺は自動追従）。
* **スマート削除**: ノードとその付随する辺を一括削除。

### 2. シミュレーション
「波」を模したWaveAgentによる動的なシミュレーション。
* **波の分岐**: ノード到達時に隣接するすべての辺へ波が分裂・伝播。
* **波の干渉システム**: 異なる発生源（Wave ID）を持つ波が正面衝突した際、互いに消滅する物理ロジックを搭載。
* **Greenberg-Hastings Cellular Automaton対応**: セル・オートマトン的な興奮・抑制状態のシミュレート。

### 3. データ管理 & ユーザビリティ
* **セーブ/ロード機能**: 構築した複雑なグラフ構造をスロットごとに保存可能。
* **Undo/Redo**: 編集ミスを恐れず作業できる、直感的なショートカット操作（Cmd+Z / Cmd+Y）。
* **レスポンシブUI**: スタイリッシュでモダンなUIを採用。

# 企画・仕様書

## 1. プロジェクト概要
本プロジェクトは、任意のグラフネットワーク上における波動の伝播、分岐、および干渉を視覚化・解析するためのシミュレーションプラットフォームです。離散的なネットワーク構造において、反応拡散系や情報伝搬のダイナミクスを直感的に構築・観察できる環境を提供します。


## 2. 主要機能（何ができるか）

### **A. インタラクティブ・ネットワークエディタ**
* **動的構築**: ノード（頂点）の設置、エッジ（辺）の接続、および削除をリアルタイムで実行。
* **直感的操作**: ドラッグ＆ドロップによるノード移動と、それに追従するエッジの動的再描画。
* **編集支援**: グリッドスナップ機能、および **Undo/Redo**（元に戻す/やり直し）によるミスのない編集体験。

### **B. WaveAgent シミュレーション**
* **波動伝播**: 選択した始点ノードから「波（Wave Agent）」が発生し、隣接するエッジに沿って定速で移動。
* **自動分岐**: ノード到達時、進入路以外の全ての接続エッジに対して新たな波を複製・生成し、網羅的な探索を実行。

### **C. セルオートマトン シミュレーション (Greenberg-Hastings Cellular Automaton)**
* **状態遷移**: 各ノードに **Excited** (興奮)、**Refractory** (抑制)、**Resting** (静止) の状態を持たせ、セルオートマトン的なダイナミクスをシミュレート。


## 3. 波動の合成・消滅アルゴリズムと実装の工夫

本アプリの核心となるのは、異なる波が衝突した際の「干渉・消滅」ロジックです。

### **アルゴリズム：IDベースの干渉識別**
単に衝突したものを消すのではなく、「同じ発生源からの波か、異なる発生源からの波か」を識別することで、論理的な干渉を実現しています。

1.  **ユニークIDの発行**: シミュレーション開始時、または新たな波の発生源ごとに `waveId` を付与。
2.  **IDの継承**: 波がノードで分裂する際、生成された子Agentは親の `waveId` をそのまま継承。
3.  **衝突判定ロジック**:
    * 2つのAgentが接触した際、それぞれの `waveId` を比較。
    * $ID_{A} \neq ID_{B}$ の場合、正面衝突（干渉）とみなし、両オブジェクトを即座に破棄（消滅）。
    * $ID_{A} = ID_{B}$ の場合、同じ波動の断片であるため、干渉させずに通過を許可。

### **実装における工夫点**
* **レイヤーベース・フィルタリング**:
    Unityの Physics Matrix を活用し、「波(Waves)」と「ノード(Nodes)」の衝突を物理的に無視。これにより、波がノードを通過するたびに消滅してしまう誤作動を防ぎ、波同士の接触のみを純粋に検知するよう最適化しています。
* **キネマティック移動**:
    `Rigidbody` を `isKinematic` に設定し、`Vector3.MoveTowards` で移動を制御。物理演算の摩擦や重力による誤差を排除し、数学的に正確な定速移動を担保しています。


## 4. 各機能の処理フロー詳細

### **① グラフ編集フロー**
1.  **入力検知**: Raycast を使用してマウス位置の空間座標を取得。
2.  **モード分岐**: `GraphManager` が現在の `EditorMode` に応じて処理を振り分け。
    * **設置**: 新規オブジェクトを生成し、隣接リスト形式のデータ構造へ登録。
    * **移動**: 選択ノードの `Transform` を更新し、紐付いたエッジの `LineRenderer` の端点を毎フレーム更新。

### **② シミュレーション実行フロー**
1.  **初期化**: `Initialize(Node startNode, Edge firstEdge, int id)` により、進行方向と識別子を確定。
2.  **更新ループ**: 毎フレーム `targetNode` との距離を計測。
3.  **ノード到達判定**:
    * 距離が閾値（**0.1f** 等）以下になった場合、次の候補エッジをリストアップ。
    * 候補が **1つ** なら方向転換、**複数** なら `Instantiate` で波を増殖。候補 **ゼロ** なら消滅。

### **③ Undo/Redo システム**
* **コマンドパターン**: 各編集操作（設置・削除等）を「コマンドオブジェクト」としてカプセル化。
* **スタック管理**: `UndoStack` と `RedoStack` の2つのスタックを用いて、LIFO（後入れ先出し）形式で操作履歴を管理。

### **④ セーブ・ロードの仕組み**
* **シリアライズ**: ノードの座標 (`Vector3`) と接続インデックスのリストを、シリアライズ可能なデータクラス（`GraphData`）に変換。
* **データ形式**: JSON形式での保存を採用。軽量かつ可読性が高く、将来的な外部ツールとの連携も容易。
* **動的生成**: ロード時は保存されたデータに基づき、ノードとエッジを動的に再生成し、隣接リストを再構築することでグラフのトポロジーを完全復元。

## 5. 技術的優位性
本アプリは、単なる視覚効果としての「波」ではなく、**グラフ理論に基づいたデータ構造**と**物理エンジンによる衝突検知**を高度に融合させています。
これにより、ノード数が数百規模に及ぶ複雑なトポロジーにおいても、破綻のない正確な波動シミュレーションが可能となっています。
